# Verification: Watch

How to run this file: bring up the production page as the [README](README.md#how-to-run-a-pass) says (`pnpm build`, `PORT=3020 pnpm start`, `http://127.0.0.1:3020/`) and start every item from a fresh browser profile, or a fresh Playwright context, at 1440×1000 unless its Setup says otherwise. To return to a clean state between sections, close the profile, or clear `wybmh-paper-arena-v2`, `wybmh-input-bindings-v1` and the IndexedDB database `wybmh-character-library-v1`. Preferences must be at their defaults: in Arena settings, **Reduced motion** and **Lower graphics quality** unticked, the policy at win 3, draw 1, loss 0, **Entries / User** 4, **Counted entries enabled** ticked; Watch sound off; the clean spectator view off; no installed characters and no asset mappings. The setup dialog keeps its choices in memory until a reload, so reload before any item whose Setup says "default choices". A fresh save already holds the two counted basketball contests, so each demo user starts with 3 entries left and counted basketball offers **No entry remaining**. **Watch outcomes are decided at lock.** Never predict a score, winner, landing or duration. Read them from the result panel, from **The contest, as it happened**, from **Export immutable recording**, or from the newest entry of `recordings` in the save. The save, `localStorage["wybmh-paper-arena-v2"]`, is a JSON envelope whose `payload` is the save as JSON text. The fields these items use are:
- `recordings[]`, with `scores`, `winner` (0, 1 or null), `duration`, `unresolvedDraw`, `attempts[]` (`actor`, `contact`, `score`, `releaseAt`, `contactAt`, `commentary`) and `setup` (`seed`, `mode` `ranked` or `exhibition`, `tie`, `secret` for **Heat check**, `showcase`, `participants[]` with `userId`, `cardId`, `strategy`)
- `ledger`, the awards
- `policy`
- `active`, the contest waiting to resume, as `{id, time}` or null

The save carries a checksum, so read it but never hand-edit it, except where an item deliberately corrupts it. Items that need a particular outcome, such as a draw, extra pairs or a push, say to lock exhibitions until one occurs. **Replayable showcase seed** (`velvet-paw-29`, Cornhole only) repeats one contest exactly. Timing items need a machine with hardware graphics: under software rendering, playback ran several times slower than wall time. Use a screen recording and step through it, or read the times from the recording. What each Device value means here:
- **mouse**: clicking the page's own buttons.
- **keyboard**: Tab, Enter, Space and Escape on the page's own controls. Watch has no game keys.
- **hidden tab**: switching to another tab in the same window. This is not blur.
- **blur**: clicking another application's window so the browser loses focus while the Watch tab stays visible.
- **two tabs**: two tabs of the same profile, both on `/`, sharing one save.
- **storage**: developer tools. Use the Application panel for localStorage and IndexedDB, and the console where an item says so. A lost graphics context is made from the console with `(c=>(c.getContext('webgl2')||c.getContext('webgl')).getExtension('WEBGL_lose_context').loseContext())(document.querySelector('.pixi-host canvas'))`. A full save is made by filling localStorage with filler keys until writes throw: 1 MB strings, then 10 KB, then 100 bytes. Remove the filler keys afterwards.
- **small screen**: responsive mode at the width the item gives.

- Whether the clean spectator view should be available in the lobby at all, where it hides **Set up showdown** and the event dock, is a product call ([Open questions and verification](../watch/lobby.md#open-questions-and-verification); B-36).

- Whether the lobby's duel cards should show a counted entry's real opponent card and order is a product call ([Open questions and verification](../watch/setup-dialog.md#open-questions-and-verification)).
- A refusal while the dialog is closing, which the document says is shown only in the error box, needs the Escape of SETUP-29 and a refusal to coincide ([Cancel and interrupt](../watch/setup-dialog.md#cancel-and-interrupt)).
- Locking refused with "Scoring policy changed. Review the setup again.", or loading another tab's recording for the same counted pairing instead of creating one, needs another tab's write to land after this tab last read the save but before **Start showdown**. The timing cannot be produced on demand ([Cancel and interrupt](../watch/setup-dialog.md#cancel-and-interrupt); [Open questions and verification](../watch/setup-dialog.md#open-questions-and-verification)).
- A reload during **Locking the contest…** keeps the contest only if the write had finished. The moment cannot be chosen ([Cancel and interrupt](../watch/setup-dialog.md#cancel-and-interrupt)).
- `configure_arena_event` changing the sport under an open dialog, and a locked contest ignoring a later change, need a browser that ships WebMCP ([Cancel and interrupt](../watch/setup-dialog.md#cancel-and-interrupt)).
