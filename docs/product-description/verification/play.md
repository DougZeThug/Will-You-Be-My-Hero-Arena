# Verification: Play

**How to run this file.**
- **Start state.** Start each section in a fresh browser profile on the production build (see [the protocol](README.md#how-to-run-a-pass)), with Arena settings at their defaults: **Reduced motion** and **Lower graphics quality** unticked. Open **Play**.
- **Setup.** Unless an item says otherwise, use the default setup: **Cornhole**, player 1 on **Keyboard · WASD** with the Doug card, player 2 an **AI player** with the Dan card.
- **Focus.** Before pressing game keys, make sure the stage has keyboard focus. It takes focus when the match opens, when it is clicked, and after **Pause game**, **Resume game**, **Sound on** or **Mute**. Tab also reaches it.
- **Between sections.** Leave the match with **Back to setup**, or reload for a clean match. Clear `wybmh-input-bindings-v2` between remapping items. It holds one entry per device; the older `wybmh-input-bindings-v1` is only read, never written.
- **Device column:**
  - **keyboard** means a physical keyboard. Keyboard 2 items need a numeric keypad.
  - **controller** means a real Xbox, PlayStation or generic pad. Press one of its buttons on the page before **Start**, because browsers reveal a pad only after that.
  - **touch** means a touch screen, or the on-screen controls clicked with a mouse where the item allows.
  - **blur** means switching to another application window.
  - **hidden tab** means switching to another browser tab.
- **Timing items.** These need a real machine at normal frame rate. Under software rendering, game time runs slow.

Not checkable by hand:

- Whether a quick tap should throw a dud rather than do nothing, unlike the on-screen controls. This is a product call ([Open questions and verification](../play/cornhole.md#open-questions-and-verification)).
- Scatter size, ±11 × (1 − accuracy) px, the Play accuracies (Dan 0.76, Doug 0.68), and precision mode narrowing scatter to 40% only if it is still active when the bag leaves the hand. Scatter is random for each throw, so checking it needs many throws measured in stage pixels ([The throw](../play/cornhole.md#the-throw), [Modifiers](../play/cornhole.md#modifiers)).
- That each match draws a fresh random seed, so the same inputs do not repeat the same scatter. This cannot be seen from one match ([Interactions with other systems](../play/cornhole.md#interactions-with-other-systems)).
- A lost WebGL context during a throw. It pauses the match with **Graphics were interrupted. Resume when the stage is back.** and discards a charge, but producing the loss needs a script against the canvas; MATCH-34 runs it from the console. This is read from the code and has not been tried on the page ([Cancel and interrupt](../play/cornhole.md#cancel-and-interrupt), [Open questions and verification](../play/cornhole.md#open-questions-and-verification)).
- The back/forward cache: whether the browser keeps a Play match, and whether it comes back paused. A browser cannot be made to use the cache on demand ([Open questions and verification](../play/cornhole.md#open-questions-and-verification)).
- An installed character without a connected rig. The test needs a pack made in Codex, and none ships with the repository; PSETUP-33 covers it when one is available ([Interactions with other systems](../play/cornhole.md#interactions-with-other-systems)).

- That on-screen presses the event cannot act on yet are buffered. The buffers last 0.14–0.23 s, too short to aim a tap into by hand ([Cancel and interrupt](../play/touch-controls.md#cancel-and-interrupt)).
- That pressing and lifting a pad without moving sends the offset for one game step. In cornhole the nudge is too small to see ([Backing out at once](../play/touch-controls.md#backing-out-at-once)).
- A lost WebGL context under the control panel. It pauses the match and rebuilds the panel as for any pause, but producing the loss needs a script; MATCH-34 runs it from the console ([Cancel and interrupt](../play/touch-controls.md#cancel-and-interrupt), [Open questions and verification](../play/touch-controls.md#open-questions-and-verification)).
- Whether the **Grapple** key cap should say which two inputs it presses. On screen it reads **Tap+Tap**; a descriptive cap such as "counter+light" is an open question, and TOUCH-06 only records the cap ([Open questions and verification](../play/touch-controls.md#open-questions-and-verification)).

Not checkable by hand:

- Counter stance is damage reduction, not a counterattack. A blow it softens now has a caption, but the stance has no animation or effect of its own. Whether it should become a counterattack is a product call ([Open questions and verification](../play/backyard-brawl.md#open-questions-and-verification)). BRAWL-21 checks the behaviour.
- A trade, both fighters' blows connecting on the same 1/60 s game step, cannot be produced on demand. A trade that knocks both out is a draw, and the result reads **Draw** ([While attacking](../play/backyard-brawl.md#while-attacking), [The hit](../play/backyard-brawl.md#the-hit)).
- A blow that connects on the very step the bout ends still counts. That step cannot be produced on demand ([Cancel and interrupt](../play/backyard-brawl.md#cancel-and-interrupt)).
- Presses made during hit-stop are read and wait in the buffer. The freeze lasts 0.05–0.08 s, too short to aim a press into by hand ([The hit](../play/backyard-brawl.md#the-hit)).
- Whether the drawn punch lines up with the moment the hit lands has not been measured. That needs frame-by-frame capture, not a hand check ([Open questions and verification](../play/backyard-brawl.md#open-questions-and-verification)).
- The damage each fighter deals is tallied internally but never shown or kept, so there is nothing to observe ([Interactions with other systems](../play/backyard-brawl.md#interactions-with-other-systems)).
