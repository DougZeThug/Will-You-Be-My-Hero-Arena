# Verification: cross-cutting

How to run this file: serve the production build and open it in a fresh browser profile as [the protocol](README.md#how-to-run-a-pass) says. Use a 1440×1000 window on a machine with hardware-accelerated graphics: under software WebGL the scripted pass ran game time and playback time several times slower than wall time, so every timing item was blocked there. Every item starts from a fresh profile on the Watch lobby unless its Setup says otherwise, with these at their defaults: the operating system's "reduce motion" preference off, so **Reduced motion** starts unticked; **Lower graphics quality** off; both sound switches off; the clean spectator view off; no saved remapping; and Play setup as it opens (**Cornhole**; **PLAYER 1** Doug Weidensaul on **Keyboard · WASD**; **PLAYER 2** Dan Weidensaul on **AI player**). "An exhibition" means **Set up showdown** then **Start showdown** with the dialog's defaults (Doug against Dan, Dan throws first, Cornhole unless the item names another sport); "a counted entry" means the same on **Counted entry · points**. Between sections, and before any item whose Setup says "fresh profile", close the profile or clear localStorage `wybmh-paper-arena-v2` and `wybmh-input-bindings-v1` and IndexedDB `wybmh-character-library-v1`, then reload. Every SOUND item needs speakers or headphones at a comfortable volume in a quiet room. Items that need a lost graphics context produce it from the developer tools console while a Watch recording plays: `const c = document.querySelector('.club-stage canvas'); (c.getContext('webgl2') ?? c.getContext('webgl')).getExtension('WEBGL_lose_context').loseContext();`. Result cells already filled come from the first scripted pass (2026-09-24); "partial" says which part of the item that pass did not see. The Device column uses [the README's values](README.md#devices-and-conditions) and two of this file's own:

- **mouse**, **controller**, **two tabs**, **hidden tab**, **blur**, **storage**, **small screen**: as in the README. **touch** means a real phone or tablet wherever the item is about touch itself (A11Y-13).
- **keyboard**: a physical keyboard. In Play, keys count only while the stage has focus. The stage takes focus when a match loads. After clicking anything else, press Tab from **Back to setup**, or use **Pause game** then **Resume game**. Clicking the stage's drawing does not focus it.
- **screen reader**: NVDA with Chrome or Firefox on Windows, or VoiceOver with Safari on macOS, speech on, in its default browse or reading mode unless a step says otherwise. Items that only check a name, role or state may use the browser's accessibility tree in developer tools instead. Items about what is *announced* need the real screen reader. The Play score strip and the Watch scoreboard are clipped to one-pixel boxes, so read them with the screen reader's reading keys or the accessibility tree.
- **WebMCP**: a browser that ships WebMCP with an assistant that can call page tools, or an emulated one. To emulate, install this before any page script runs, for example with Playwright's `addInitScript` or a local override of the page: `document.modelContext = { registerTool(tool, options) { (window.__webmcp ??= {})[tool.name] = { tool, options }; return Promise.resolve(); } };`. Call a tool from the console with `await __webmcp.read_arena.tool.execute({})` or `__webmcp.configure_arena_event.tool.execute({ event: 'football' })`. A refusal is thrown as an `Error` carrying the message. The page looks only for `document.modelContext` (see AGENT-32). Mark emulated results "(emulated WebMCP)": they prove the page's handling, not a real assistant's.

AI-player items need nothing beyond these; a match with only AI players needs only a mouse.

Not checkable by hand:

- Watch contests have no AI players, because both sides are simulated in full before playback. There is no AI to look for in Watch ([Modifiers](../cross-cutting/ai-players.md#modifiers)).
- The AI reads the true state of the game on every step, with no reaction delay beyond its own schedule. That has no visible sign beyond AI-09 to AI-15 ([While acting](../cross-cutting/ai-players.md#while-acting)).
- A card's stats and abilities work for the AI as for a person. A person's input cannot be reproduced exactly enough to compare the two ([Modifiers](../cross-cutting/ai-players.md#modifiers)).
- Whether the Brawl AI should make a fresh decision while the match is paused is a product call, and players cannot see it directly ([Open questions and verification](../cross-cutting/ai-players.md#open-questions-and-verification)).
- Whether the AI keeps playing unseen after a lost WebGL context is unknown. Play has no handler for it, and the document makes no claim to test ([Cancel and interrupt](../cross-cutting/ai-players.md#cancel-and-interrupt)).
- An installed card as an AI player needs a finished `.arena-character.json` pack with a connected rig, and none ships with the repository ([Interactions with other systems](../cross-cutting/ai-players.md#interactions-with-other-systems)).
- The engine's reference AI-against-AI results use the fixed seed `live-proof`. The page chooses its own seed, so they cannot be reproduced there ([Open questions and verification](../cross-cutting/ai-players.md#open-questions-and-verification)).
