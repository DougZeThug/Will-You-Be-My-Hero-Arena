# Verification: foundations

How to run this file: serve the production build of commit `3b4ec62` (see [How to run a pass](README.md#how-to-run-a-pass)) and open `http://127.0.0.1:3020/` in a fresh browser profile on a machine with a real GPU; software WebGL runs game time and playback time several times slower than wall time, so every timing item is meaningless there. Every item starts from a fresh save in a fresh profile unless its Setup says otherwise: no `wybmh-paper-arena-v2` or `wybmh-input-bindings-v1` in localStorage and no `wybmh-character-library-v1` in IndexedDB. Keep these preferences at their defaults: the operating system's "reduce motion" setting off (the page's **Reduced motion** starts from it), **Lower graphics quality** off, Watch and Play sound off, the clean spectator view off, browser zoom 100%, the window about 1440×1000 unless the item says otherwise, Num Lock on, and no controller plugged in unless the Device column says `controller`. Between sections, and after any item that writes the save, bindings or library, close the profile or clear those three stores in developer tools and reload. Shorthand used below: **Play defaults** is the Play tab just opened (Cornhole, **PLAYER 1** Doug on **Keyboard · WASD**, **PLAYER 2** Dan on **AI player**); **stage focused** means the match has finished loading and nothing has been clicked since, or the tester has pressed Tab from **Back to setup** to reach the stage (clicking the stage's drawing does *not* focus it); **cornhole aiming** means the 1.45 s entrances are over and player 1, who throws first by slot order, is aiming. Device values: `mouse` is pointer clicks; `keyboard` is a physical keyboard, with a numeric keypad for keyboard 2 items, pressed while the stage is focused unless the steps say otherwise; `controller` is a real Xbox, PlayStation or generic pad with a button pressed on the page before **Start**, except that items needing an exact analog value (0.1, 0.15, 0.18, 0.2, 0.55) use the emulated controller of `tests/browser/input.spec.ts`, because nobody can hold a trigger at an exact fraction by hand, and are recorded as emulated; `touch` is a touch screen or the on-screen controls clicked with a mouse; `two tabs` is two tabs of the same profile (they share one save); `hidden tab` is switching to another browser tab, which is not the same as `blur`, clicking into another application window; `storage` is developer tools, to read or edit localStorage and IndexedDB, block storage, or run a console command (focusing developer tools blurs the page window, which pauses a Play match, so click back into the page before continuing); `small screen` is responsive mode at the width the item gives.

Not checkable by hand:

- The exact buffer lengths (0.14 s in cornhole, 0.18 s in the Dash, 0.23 s in the Brawl), the four-press limit, a newer press of the same action replacing an older one, and only pressed and double-tapped inputs being buffered. The windows are too short to time by hand and nothing on screen shows the buffer; `tests/live-tests.mjs` covers them against the Lab ([Buffered presses](../foundations/input-model.md#buffered-presses)).
- The 1.2 s press history kept for combos ([Starting](../foundations/input-model.md#starting)).
- Down, forward, special within 0.65 s: it makes the same move as special alone, so it cannot be told apart on screen (B-28). "Forward" meaning toward the opponent is only visible through this combo ([Chords and combos](../foundations/input-model.md#chords-and-combos)).
- The repeated signal after 0.36 s and every 0.1 s: no current event uses it, so nothing shows it ([While committed](../foundations/input-model.md#while-committed)).
- AI players never pausing: there is nothing to provoke ([Devices](../foundations/input-model.md#devices)).
- Slots 3 and 4 always starting from the defaults: an added slot starts as **AI player**, and choosing a device for it replaces its bindings with that device's defaults anyway, so a saved entry for slot 3 or 4 can never show on screen (B-18) ([Modifiers](../foundations/input-model.md#modifiers)).
- The technical note that the session watches pause before the event's own controls. It is a design statement; its visible effects are INPUT-29 and INPUT-33 ([Cancel and interrupt](../foundations/input-model.md#cancel-and-interrupt)).
- Whether a controller whose browser slot changes mid-match is noticed as a disconnect. The browser decides slot changes, and they cannot be produced on demand ([Open questions and verification](../foundations/input-model.md#open-questions-and-verification)).
- Whether Backspace can navigate back when stage focus is elsewhere. Current browsers do not navigate on Backspace; it needs an older browser that does ([Edge cases](../foundations/input-model.md#edge-cases)).
